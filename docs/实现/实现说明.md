## 1. 怎么跑

```bash
npm install
npm run gen:assets     # 生成本地占位素材（零外网、无需 ffmpeg）
npm run build          # tsc --noEmit（源码 + 示例）→ vite lib → 类型声明 → 示例页
npm test               # node tests/unit-test.mjs（零依赖自测）
npm run accept         # scripts/acceptance.ps1（退出码 0/1）
npm run dev            # 独立示例页 http://127.0.0.1:5181/
```

验收脚本覆盖 7 组共 25 项：红线机检、零运行时依赖与分层、类型检查、构建、素材、自测、运行态（headless 浏览器：素材解码抽样 + **6 路真播与单路失败隔离** + 示例页）。

## 2. 架构分层（契约 §11.3-① 的落实）

```
src/index.ts                唯一公开入口
   ├── src/core/**          机制层：零 react 依赖 —— node 可直接跑（自测即跑这一层）
   └── src/react/**         视图层：唯一允许依赖 react 的地方
```

- 控制器是**纯逻辑**：不触碰 DOM，一切媒体元素命令经注入的 `MediaViewPort` / `MediaElementHandle` 抵达 DOM；
  未挂载视图时命令照常计入状态机与诊断（这正是"零依赖单测脚本"能覆盖状态机的原因）。
- 叠加层与画面**共用同一份内容框**（`controller.getContentBox(id)` / `getViewState(id)`），
  避免两套坐标口径导致的错位（CTR-MDP-OVL-01）。
- 时间语义一律取注入的 `IClock.nowMs()`；计时器可注入（`MediaControllerImpl` 的 `deps.timer`），
  使图像流轮播、不可见延迟暂停、事件限频在单测里完全可复现。

## 7. 已知取舍（写下来避免以后当成 bug）

1. **"最近一次 play"的口径**：`pickAudible` 是纯函数、拿不到调用历史，故按清单顺序取候选；
   控制器在调用前把候选按 `playSeq` 重排，使"最近 play"口径可复现。
2. **事件限频与注入时钟**：同一毫秒内的多次状态迁移会被 `throttleMs` 合并成一条事件——
   这是 §5.1 的频率约束（不是丢事件），需要逐条观察时应把注入时钟推进到窗口之外。
3. **`clamped` 的语义边界**：`seek` 只在"超出 `durationMs`"时置 `clamped`；负值被夹到 0 属于区间内规整，不置 `clamped`。
4. **重复 `play`**：`playing` 与 `loading` 两个状态下都返回幂等成功（MUST NOT 重新起一次加载）。
5. **内容框在容器尺寸为 0 时**：回落到媒体自身尺寸基准（而不是零矩形），
   保证"隐藏前最后一帧"仍可算出合法叠加位置；尺寸恢复后立即重算。
